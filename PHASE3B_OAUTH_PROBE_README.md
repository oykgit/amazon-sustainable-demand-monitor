# Phase 3.0B — controlled OAuth probe
Add the three files at their relative repository paths. No existing files change. Run locally with `python -m pytest -q tests/test_phase3b_oauth_probe.py tests/test_ebay_public_keys.py`. After the webhook service deploys the commit, use its private Render Shell (if available) and run `python phase3b_oauth_probe.py --authorize-token-request` in the repository directory. The explicit switch permits a single production client-credentials request to the fixed eBay OAuth endpoint. No token, credentials or exception details are printed; redirects are refused. No Browse requests, database writes, public diagnostic endpoint or live deletion activation. Without the switch no request is made. Do not put credentials in the command. If Shell is unavailable, the existing Phase 3.0A Production Readiness Evidence workflow has an OAuth-only option requiring EBAY_CLIENT_ID and EBAY_CLIENT_SECRET in GitHub Actions secrets; do not duplicate them unless you choose that alternative. Live OAuth acceptance is not permission to collect data: production storage, restoration and deletion notification handling remain outstanding. Contact eBay developer support regarding the registered endpoint rejecting POST and possible missed notifications.
